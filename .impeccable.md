## Design Context

### Users
Exam proctors, instructors, and operators running AISENTINEL on the front-node device during live classroom assessments. They need to authenticate quickly, configure the current monitoring session, watch the live annotated feed, and review incident evidence without leaving the dashboard.

### Brand Personality
Trustworthy, vigilant, technical. The interface should feel controlled, serious, and dependable, with enough urgency to make alerts unmistakable without making the default state feel chaotic.

### Aesthetic Direction
Use the provided Sentinel references as the primary visual direction: a dark control-room dashboard with deep navy surfaces, restrained electric-blue actions, high-contrast alert colors, and clear monitoring-focused information hierarchy. Avoid playful consumer-app styling, light cheerful palettes, and generic admin-dashboard patterns.

### Design Principles
- Prioritize fast situational awareness over decorative density.
- Keep login and session setup low-friction for on-device operators.
- Make live cheating alerts impossible to miss and evidence easy to open.
- Treat saved evidence as grouped incident records, not loose image files.
- Preserve a calm baseline state so alert states read as genuinely urgent.
